01 / 为什么

不是所有公司都能重写一套系统

给现有系统加 AI，难的地方从来不是「接个大模型」，而是这三件事。

问题一

模型不认识你的接口

通用大模型知道怎么写 SQL，但不知道你有 /api/stats/sales，更不知道它收 days 还是 startDate。不给说明书，它只能瞎猜。

问题二

没人敢让它直接动手

让 AI 改生产数据、改线上页面，一次误操作就是事故。没有确认闸门和备份，「能改」反而变成风险。

问题三

答错了查不出原因

它说「这个月卖了 6188」，你不知道数字从哪来。没有工具调用记录、没有依据、没有反馈闭环，就没法优化。

02 / 能做什么

四种能力，都落在你系统已有的东西上

没有凭空造数据，没有绕过业务逻辑。它调的是你的接口、查的是你的库、改的是你的文件。

SCAN

扫接口

读源码把路由、参数、风险等级扫成一份清单（manifest.json）。扫不准的地方，管理端可以一条条改。

node cli/index.mjs init --root . --name "门店后台"
API

调接口

清单里的每个接口都会变成模型能调用的工具。接口自测会先真调一次，把真实返回结构写回说明——模型不用再猜字段名。

GET /api/stats/sales → {revenue, orders, top[]}
DB

查数据库

跨表统计而接口不够用时，允许写只读 SQL。语句级护栏：只放行 SELECT，行数有上限，写操作在驱动层就拦住。

SELECT name, SUM(qty) FROM orders GROUP BY name
FILE

改页面

纯静态站没有接口，就让助手直接改文件。读原文 → 生成逐行 diff → 你点确认才落盘，改坏了能一键回滚。

- ¥128 → + ¥138 （只动这一行）

03 / 怎么接

两种接法，选择权在你这边的技术栈

四层里只有「挂载方式」绑 Node，其余三层跟宿主语言无关。所以 PHP、Java、.NET 的老系统同样能接。

前置 接入之前先准备三样东西：一个 OpenAI 兼容的接口地址、一个 API Key、一个 支持 tool calling 的模型名。填在 .sidepilot/config.json 的 llm 段。 DeepSeek、通义、Kimi、智谱、本地 Ollama 都行——缺一样，助手就是个空壳。
还没有 Key 的话，可以用中转站（一个 Key 调多家模型）： openlux.ai 链接含邀请码，作者自己在用
A 嵌入模式 · 同进程

两行代码，跟业务跑在一起

适用于 Node 项目：Express / Koa / 原生 http

助手作为中间件挂进现有服务，共用同一个端口和同一份数据连接，不用额外起进程。

// 入口文件，所有路由注册之后
import { createPilot } from './vendor/sidepilot/src/index.mjs';
createPilot({ config: './.sidepilot/config.json' }).attach(server);
B 独立模式 · 反向代理

业务代码零改动

适用于 PHP / Java / .NET / Python / 纯静态站

助手单独跑一个进程，业务站把 /pilot 转发过去。对业务系统来说，它只是多了一个路径。

# nginx 三段
location /pilot/ {
    proxy_pass http://127.0.0.1:7788;
    proxy_buffering off;   # SSE 必须关
}
项目类型接入方式业务侧改动建议能力域
Node（Express / Koa / 裸 http）嵌入，同进程入口加 2 行api + db + file
PHP（Laravel / ThinkPHP / 原生）独立 + nginx 反代0 行api
Java（Spring Boot）独立 + nginx / 网关0 行api
.NET（ASP.NET）独立 + IIS ARR0 行api
纯 HTML / 静态站独立 + nginx0 行file
04 / 安全

「能动手」和「敢让它动手」是两件事

默认策略一律偏保守：能不执行就不执行，能只读就不写，必须写就一定有人点确认。

  • 目录白名单文件编辑只能落在配置指定的目录内，白名单外的路径直接拒绝，不给"随手改一下"的机会。
  • 改前备份每次落盘前把原文完整存进 .sidepilot/backups，回滚时不用靠 diff 反推。
  • 语法校验改 HTML 先做标签平衡检查，改完不合法就不写盘，避免把页面改成一堆死标签。
  • 逐行差异确认写之前把 diff 摆在你面前，只动那几行。不点确认，一个字都不会变。
  • 原子写入先写临时文件再替换，中途断电也不会留下半截文件。
  • 一键回滚改错了在文档站点「修改历史」里回滚，用的是备份的原文，不是靠模型再改一遍。

操作审计 · 谁在什么时候动了什么

14:02 调用工具 sales_stats（days: 30） 张三
14:03 修改文件 www/index.html，第 116 行 · ¥128 → ¥138 张三
14:05 写操作被拒绝 · product_create 李四
14:09 修改配置 llm.model admin
审计只记动作和对象，不记密钥内容。会话、工具流水、文件改动、配置变更各留一条， 配合 x-pilot-user 请求头做人员归属——出事能查到人，这是能不能进企业的分界线。
